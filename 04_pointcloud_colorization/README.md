# PointCloudProcessor

This repository contains the 3D reconstruction post-processing and automated crack-width measurement code used in the paper. It takes a fused LiDAR map, synchronized camera poses, raw images, and optional refined crack masks, then produces colorized point clouds, mask-projected point clouds, per-frame visible point clouds, and 3D crack-width measurement results.

## Pipeline Position

```text
ROS bag
  |
  |-- 02_rosbag_extraction
  |    |-- raw images
  |    |-- LiDAR PCD frames
  |    `-- IMU/location/magnetic CSV
  |
  |-- visual-inertial-LiDAR fusion / mapping
  |    |-- fused map: scans-clean.pcd or ronghe.pcd
  |    `-- camera/visual odometry text files
  |
  |-- CrackModel0823 segmentation
  |    `-- refined crack masks
  |
  `-- PointCloudProcessor
       |-- point cloud cropping and optional MLS smoothing
       |-- keyframe selection
       |-- view culling / hidden point removal
       |-- optional NID or manual camera-LiDAR pose refinement
       |-- color and crack-mask projection to 3D
       `-- crack-width estimation from skeleton, edges, and local 3D planes
```

## Environment

The C++ processor was developed for Ubuntu/ROS Noetic-style environments.

Required system dependencies:

- ROS Noetic packages: `roscpp`, `rospy`, `sensor_msgs`, `geometry_msgs`, `nav_msgs`, `std_msgs`, `tf`, `cv_bridge`, `eigen_conversions`
- PCL
- OpenCV
- Eigen3
- Boost filesystem and program_options
- Ceres Solver 2.1 or newer
- OpenMP
- Qhull
- Iridescence/GLK/GUIK for the manual calibration GUI
- Vendored Sophus and nlohmann/json headers under `PointCloudProcessor/thirdparty`

Example setup on Ubuntu:

```bash
sudo apt update
sudo apt install -y \
  cmake make git \
  libpcl-dev libopencv-dev libeigen3-dev libboost-all-dev \
  libomp-dev libqhull-dev libfmt-dev
```

The current C++ source uses Ceres headers such as `ceres/manifold.h` and `ceres/autodiff_first_order_function.h`. Ubuntu 20.04's default `libceres-dev` package is Ceres 1.14 and is too old for this build. Install Ceres 2.1+ from source or from a newer binary package before running CMake.

If your distribution does not package Iridescence, build it from source:

```bash
git clone https://github.com/koide3/iridescence --recursive
mkdir -p iridescence/build
cd iridescence/build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j$(nproc)
sudo make install
```

For the Python crack-width scripts:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-width.txt
```

## Input Data Layout

A reproducible processing folder should look like this:

```text
dataset/
|-- ronghe.pcd                    # fused LiDAR map or reconstructed point cloud
|-- visual_odom.txt               # visual/camera timestamps
|-- visual_odom_in_lidar_ts.txt   # pose states in LiDAR timestamp
|-- vo_interpolated_odom.txt      # generated by make_vo_odom_for_fastlio.py
|-- raw_images/
|   `-- 1721034888.068144.jpg
|-- masks/
|   `-- 1721034888.068144.png
`-- mask_select/                  # used by crack-width scripts
    `-- 1721034888.068144.png
```

The odometry file consumed by the C++ binary is whitespace-delimited:

```text
timestamp x y z qw qx qy qz
```

Image filenames must be `timestamp.jpg`. Mask filenames must be `timestamp.png` and match the odometry timestamps.

The current code hard-codes the camera intrinsics, distortion coefficients, and image size used in the paper dataset:

```text
image size: 4096 x 3000
fx=4818.200388954926, fy=4819.10345841615
cx=2032.4178620390019, cy=1535.1895959282901
distortion=[0.003043514741045163, 0.06634739187544138,
            -0.000217681797407554, -0.0006654964142658197, 0]
```

For a different camera, update these values in `PointCloudProcessor/include/PointCloudProcessor.hpp` and `PointCloudProcessor/src/PointCloudProcessor.cpp`.

## Run 3D Colorization and Mask Projection

The recommended public entry point is the wrapper script. It validates the input paths, optionally creates `vo_interpolated_odom.txt`, and forwards explicit parameters to the C++ binary:

```bash
DEMO_DATA=../CCIE2026_Crack3D_demo_data

bash 04_pointcloud_colorization/run_pcd_colorization.sh \
  --data-root "$DEMO_DATA/colorization_smoke" \
  --point-cloud "$DEMO_DATA/colorization_smoke/scans-crop.pcd" \
  --odom "$DEMO_DATA/colorization_smoke/vo_interpolated_odom.txt" \
  --images "$DEMO_DATA/colorization_smoke/raw_images" \
  --output "$DEMO_DATA/colorization_smoke/output" \
  --enable-mls 0 \
  --enable-nid 0 \
  --enable-manual 0
```

If `--odom` is omitted and `visual_odom.txt` plus `visual_odom_in_lidar_ts.txt` are present, the wrapper runs:

```bash
python3 PointCloudProcessor/scripts/make_vo_odom_for_fastlio.py --root_dir "$DEMO_DATA/colorization_smoke"
```

Available flags:

| Flag | Meaning |
| --- | --- |
| `--data-root` | Dataset folder containing the point cloud, images, masks, and odometry. |
| `--point-cloud` | Input fused map. Defaults to `scans-crop.pcd`, then `ronghe.pcd`, then `scans.pcd` under `--data-root`. |
| `--odom` | Interpolated odometry text file. Defaults to `vo_interpolated_odom.txt`. |
| `--images` | Timestamp-named raw or color-balanced image folder. Defaults to `raw_images/`. |
| `--masks` | Optional timestamp-named crack mask folder. Empty disables mask projection. |
| `--output` | Output folder. Defaults to `--data-root`. |
| `--binary` | Built `PointCloudProcessor` binary. Defaults to `PointCloudProcessor/build/PointCloudProcessor`. |
| `--enable-mls` | Enable Moving Least Squares smoothing after map cropping. |
| `--enable-nid` | Enable multi-frame NID-based pose refinement. |
| `--enable-manual` | Enable manual 2D/3D correspondence GUI for pose refinement. |

`--enable-nid` and `--enable-manual` are alternative pose-refinement modes. Use only one of them for a run. The GitHub smoke test keeps both disabled.

For the bundled companion data package:

```bash
bash scripts/run_colorization_smoke.sh ../CCIE2026_Crack3D_demo_data
```

## Crack-Width Measurement

The width measurement code is in `PointCloudProcessor/scripts/genNormAndDistanceMask.py`. It uses per-frame visible PCDs, selected crack masks, and raw images to compute local 3D planes and recover 3D edge points from 2D crack skeleton points.

Expected folder layout:

```text
dataset/output/
|-- filtered_pcd/
|   `-- 1721034888.068144.pcd
|-- mask_select/
|   `-- 1721034888.068144.png
`-- raw_images/
    `-- 1721034888.068144.jpg
```

Run:

```bash
DEMO_DATA=../CCIE2026_Crack3D_demo_data

python3 PointCloudProcessor/scripts/genNormAndDistanceMask.py \
  --data-root "$DEMO_DATA/width_measurement_demo" \
  --camera-config configs/camera_4096x3000_paper.json \
  --stage all \
  --selected-points-json "$DEMO_DATA/width_measurement_demo/selected_points.json"
```

For the bundled companion data package:

```bash
bash scripts/run_width_measurement_demo.sh ../CCIE2026_Crack3D_demo_data
```

CLI options:

| Flag | Meaning |
| --- | --- |
| `--data-root` | Folder containing `filtered_pcd/`, `mask_select/`, and `raw_images/`. |
| `--camera-config` | JSON camera intrinsics and distortion. |
| `--stage` | `precompute`, `measure`, or `all`. |
| `--selected-points-json` | Non-interactive skeleton point selections. Required unless `--manual-select` is used for measurement. |
| `--manual-select` | Open the OpenCV manual point-selection UI. |
| `--fx --fy --cx --cy` | Override intrinsics without a JSON config. |
| `--distortion` | Override distortion as `k1 k2 p1 p2 k3`. |

Main outputs:

```text
dataset/output/
|-- norm_masks/
|-- distance_mask/
|-- edt_skeleton/
|   |-- *_edt.png
|   |-- *_edt_vis.png
|   |-- *_skeleton.png
|   `-- *_skeleton_edge_pts.png
`-- crack_width_3d_results.json
```

The script workflow is:

1. Threshold the refined crack mask.
2. Compute Euclidean distance transform and skeleton.
3. Estimate projected 3D normals and distance masks from each visible point cloud.
4. Let the user select representative skeleton points in an OpenCV window.
5. Estimate local skeleton direction from image gradients.
6. Trace left/right 2D crack edges along the normal direction.
7. Fit a local 3D plane near the skeleton point.
8. Search for 3D edge points whose projection matches the 2D edge locations.
9. Save crack width in millimeters to JSON and visualization images.

## Auxiliary Scripts

## Open-Source Checklist

- Include `src/`, `include/`, `cmake/`, `scripts/`, `docker/`, `CMakeLists.txt`, `thirdparty/`, and this README.
- Keep only the required third-party headers; do not commit generated third-party build artifacts.
- Do not commit large `.pcd`, `.bag`, generated `filtered_pcd/`, `cloudInWorld*.pcd`, or local reconstruction datasets.
- Keep public entry points parameterized; avoid adding local absolute paths back into scripts.
- Keep one tiny demo dataset only if it is small enough for Git. Publish full reconstruction data separately.
- Document the exact camera intrinsics, image size, and coordinate conventions for any public dataset.
